# Отчёты и разбор ZAP

Этап 3 [плана](zap-plan.md), 2026-10-16. [CI-обвязка](zap-ci.md) реализована
2026-10-17, живой rollout ещё не проверен. Активный скан — следующий этап.
Команда `npm run test:zap:pilot` сохраняет в
`test-results/zap-pilot/<timestamp>-none/`:

- `pilot.json` — покрытие, очередь, длительность, точные ZAP/addon versions,
  digest образов, SHA и dirty. Это техническая диагностика, не список уязвимостей.
- `report.json` — очищенные группы находок, исходные risk/confidence, решения,
  предупреждения и доступность сравнения.
- `summary.md` и автономный `report.html` — человекочитаемое представление.
- `run.json` — статус, SHA/dirty/image и хеши scanner/scope/policy для сравнения.

При ошибке санитайзера детальные отчёты не экспортируются: остаются безопасные
диагностика и сводка «отчёт/сравнение недоступны». Не открывай raw-экспорт вместо
этой сводки. Ошибка не означает отсутствие проблем. Штатный cleanup удаляет
контейнер с сырой историей; последствия аварии Docker проверяются вручную.

## Сначала изменение, затем решение

Текущий формат JSON — v2: хеш идентичности называется `identity`. Поле `key`
в прежнем локальном v1 давало ложные срабатывания Gitleaks как API credential;
проверка секретов не ослаблялась. Git baseline перенесён в v2 без изменения
самих идентификаторов и исходных фактов. Публичный источник Google в CSP
обозначается `google-accounts`, чтобы не смешивать метку с OAuth credentials.
Старые HTML можно читать, а JSON v1 не
принимается как новый baseline — для него нужен новый прогон текущей команды.

`new / known / changed / uncompared` описывают сравнение. Отдельные
`new / confirmed / expected / false-positive / accepted-risk` — результат разбора.
Таким образом, `known + new` означает повтор неразобранной проблемы, а
`known + confirmed` — известную проблему, которую всё ещё надо исправлять.
Риск и достоверность сканера не понижаются. Разобранные ожидаемые находки идут
ниже требующих внимания, но сохраняются в отчёте со счётчиками и пояснением.

Ключ включает вариант правила, локальный профиль, маршрут, метод, персону,
представление, назначение Action, вид query и параметр/место. Нормализуются только
явные шаблоны space ID, `_rsc` и immutable static assets. Неизвестные пути/query,
Actions и evidence редактируются и становятся несопоставимыми; их нельзя
автоматически объявить известными или подавить решением. Это намеренный остаток,
а не универсальный санитайзер произвольного содержимого.

Сравнение требует двух completed-отчётов одинаковых scanner/scope/target и версии
нормализации. Scanner учитывает digest ZAP, версию ядра и addons. При несовместимой
или невалидной истории сравнение недоступно и прежние решения не применяются.
Без начальной истории допустимы только явно заданные решения по точным признакам.
Изменение risk/confidence/evidence помечается changed и требует нового разбора.
Исчезновение находки не объявляется исправлением автоматически.

## Начальная точка сравнения

После просмотра локального completed-отчёта:

```powershell
npm run test:zap:baseline -- test-results/zap-pilot/<timestamp>-none/report.json
```

Команда принимает только валидный очищенный `report.json` из каталога пилота,
записывает `config/zap/baseline.json`. Проверь diff перед commit. Это явное локальное
принятие точки сравнения, не автоматическое принятие рисков и не разрешение PR
обновлять доверенную историю. CI-обвязка берёт baseline/политику из отдельного
checkout default branch и отдельно показывает факт изменения этих файлов в PR.
Незакоммиченный dirty-прогон идентифицируется локальным image ID, не только HEAD.

## Решения и пересмотр

Реестр — `config/zap/decisions.json`. Условия точные; разрешены конечные списки
правил/маршрутов/персон, но не regex или wildcard. Указываются ID, владелец,
решение, код причины, ссылка, дата и пересмотр не позже 90 дней. Коды причин
раскрываются русскими пояснениями в отчёте; произвольный текст из сканера не
копируется. Для нового класса причины расширь проверяемый словарь и документацию.
`accepted-risk` требует ссылки на модель угроз и отдельного решения владельца.
Сейчас принятых рисков в реестре нет.

Просроченные/невалидные/дублирующиеся решения не применяются; конфликт двух
совпавших решений тоже требует разбора. Предупреждение видно в сводке. Смена
признаков или changed возвращает находку в `new`. По умолчанию ничего не
отключается в сканере: вместо native Alert Filters используется слой решений
после очистки, чтобы сохранить исходные severity/confidence и все примеры.

## Первичный разбор

### Locale cookie

`ZAP-001`: отсутствие HttpOnly у `NEXT_LOCALE` ожидаемо для настройки языка,
не дающей авторизации. Только GET публичных локализованных HTML-страниц,
анонимный режим, точные cookie flags и Low/Medium из проверенного локального
HTTP-профиля. Это не исключение для session-cookie или production HTTPS.

### Flag image

`ZAP-002`: SRI-предупреждение о предзагрузке публичного изображения флага
помечено expected. Evidence должно точно соответствовать известному preload
flagcdn и канонизируется в безопасную метку; исключение не относится к скриптам,
CSS или произвольным внешним ресурсам.

### Static CORS

Словарь поддерживает узкий разбор публичной immutable-статики без Set-Cookie;
готового исключения CORS сейчас нет: в текущем локальном отчёте оно не найдено.
Ранее увиденный на production шрифт не основание исключать API или auth-ответы.

### CSP и CSRF

`ZAP-003`: варианты CSP 10055-4/5/6 подтверждают неполную политику из
`next.config.ts`. Это confirmed, а не false-positive или accepted-risk.
Отсутствуют ограничения script/style/default-src; это пробел дополнительного
защитного слоя, не доказательство воспроизводимого XSS. Он записан в
[открытых вопросах модели](threat-model/risks.md#внедрение-zap).

CSRF 10202 остаётся неразобранным и несопоставимым: отсутствие распознанного
токена в HTML не доказывает отсутствие серверных origin/Action-проверок.
Информационные session-marker/SPA не означают уязвимость и сохраняются отдельно.
Неизвестные evidence требуют расширения безопасного извлечения и тестов,
а не массового исключения всей категории.

## Проверка защиты отчёта

Юнит-тесты `test/zap/report.test.ts` проверяют удаление приватных маркеров из
query/cookie/body/ошибок, неизвестные CSP/CORS, разделение ролей/Actions,
new/known/changed, expiry/конфликты и отказ при HTML/невалидной схеме.
Это проверка перечисленных форм и словарей, не доказательство всех утечек.
Предел размера API/config — 16 MB, до 20 000 alerts.

```powershell
npm run test:zap:pilot -- --probe=report
```

Проба добавляет ошибочный alert с приватным маркером внутри контейнера.
Ожидаются error, ненулевой код, отсутствие детальных артефактов и маркера
во всех экспортированных файлах. Сырые HTTP/HTML, значения cookie, Session DB,
trace/video/screenshots не копируются на хост. Эти файлы не публикуются в CI
локальной командой. Для CI есть отдельный publisher с повторной проверкой схемы;
фактическая публикация и права job ещё требуют проверки в живом Actions.

## Приёмка 2026-10-16

Локальная production-сборка и 22 выбранных E2E прошли с реальным ZAP;
очередь опустела. Проверено применение трёх решений: 9 групп expected и
18 CSP-групп confirmed, исходный риск сохранён. Число групп — следствие
разделения маршрутов/персон/правил, а не количество отдельных уязвимостей.

Повторный completed-проход относительно явно принятой точки распознал
36 известных групп; рост confidence одного session-marker выделил changed.
Уточнение канонизации CSP с сохранением `;` выделило 18 changed вместо
молчаливого применения прежнего решения; новая форма просмотрена и принята
как точка сравнения. Это изменение формата evidence, не новый XSS.

Финальный проход `1792152866628-none`: completed, 22/22, 546 запросов,
pending=0, 68 секунд на готовом стенде; сравнение available, 36 known,
30 uncompared, new/changed=0. Решения: 9 expected, 18 confirmed, 39 new
(неразобранные, включая известные). High=0 не доказывает отсутствие уязвимостей.
Baseline — явно просмотренный предыдущий completed-проход
`1792152660444-none`. Все данные synthetic/local-http; точные image/SHA/dirty
и версии сохранены в metadata. Штатная очистка контейнеров/network подтверждена.

Проба report дала error/invalid-alert; экспортированы только pilot.json,
run.json и summary.md, приватного маркера нет. Неверный путь и валидный
incomplete-отчёт отклонены командой baseline, прежний файл не изменился.
Локальные проверки: lint, typecheck, 714 юнит-тестов (20 для отчётов),
456 security-контрактов. Обычный E2E-набор на этом этапе не менялся;
его 143 passed относятся к приёмке этапа 2.
