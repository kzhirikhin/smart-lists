## Внедрение ZAP

2026-10-15 согласован [план](../zap-plan.md); 2026-10-16 реализован
[локальный пассивный пилот](../zap-pilot.md), A103, и
[отчёты/triage](../zap-triage.md), A104. Проверка выбранных сценариев,
сессий/контекстов и очереди есть; очищенные отчёты, точные решения/expiry и
локальная точка сравнения реализованы. 2026-10-17 добавлен
[независимый advisory workflow](../zap-ci.md), A105; в Actions проверены
completed/error/incomplete/skipped и публикация. PR #231 слит; main-run
39000032408 completed, trusted policy/baseline из main, comparison available,
три решения применены. Этап 4 завершён. [Этап 5](../zap-manual.md) проверен локально:
internal gate и два правила/три входа, синтетические сессии, отдельные phase/source
отчёты; completed A/B, контрольная XSS-мишень и session/precondition/budget-пробы
прошли. Ручной Actions workflow опубликован через PR #235 и проверен на main:
run 39045344867 completed A/B, 546 passive/pending=0, 41 active, dirty=false,
по 6 успешных изменений поля обеих Actions. Девять safe-файлов точно
воспроизведены, token read-only, API retention 30 дней. Actions fault/forced
timeout не воспроизводились; успешная cleanup не доказательство hard cancel.
Сигнала давности пока нет.
CodeQL в PR выявил cache poisoning при checkout произвольного SHA: input убран,
checkout закреплён за github.sha выбранной ветки/тега; общий npm
cache и автоматическое кеширование package manager выключены. Намеренный
reflected XSS учебной control-мишени учтён отдельно (CodeQL #7, used in tests),
а не как исправленная уязвимость приложения.
Cache runtime token ограничен `cache-mode: none`; отсутствие cache-шагов само
по себе не предотвращает cache poisoning исполняемым кодом выбранного SHA.
Пилот не доказывает полноту проверки приложения и deployed-конфигурации.

Принятое решение: ZAP advisory, включая High и сбои; обязательные E2E/другие
gates остаются прежними. Новая High требует приоритетного разбора владельцем
до следующего планового релиза. Пересмотр неблокирующей политики: повторное
игнорирование High/ошибок, расширение аудитории за whitelist, второй оператор
или требование release SLA. Изменение блокирующих правил — отдельное решение.

В локальном пилоте копия синтетического session-трафика остаётся в удаляемом
контейнере; наружу выходят счётчики/статусы и признаки по конечным словарям. Fixed target/БД, internal
network и probe ограничивают случайный доступ к внешним системам. Потеря
сессии/прокси/покрытия или незавершённая очередь не дают completed (A103, T*).
Проверка GitHub 2026-10-17 подтвердила read-only job token, отсутствие ZAP в
required checks и expires_at артефакта через 30 дней. Это датированное
наблюдение, не защита от drift и не наблюдение будущего удаления. `-silent`
устраняет внешние update/telemetry; актуальность сканера требует отдельного
review digest/addons. Остаток: нет полной
проверки всех входов и контроля уведомлений. Trusted-история берётся из явно
просмотренного Git baseline default branch, не автоматически последнего run.
Неизвестные evidence, включая CSRF,
не сопоставляются и не исключаются автоматически; нужен отдельный разбор.
Принудительное завершение хоста/сбой Docker
может оставить контейнеры/трафик; штатная cleanup проверяется, daemon/ядро доверены.
Тесты этапа 3 проверяют перечисленные секретные маркеры/формы/HTML и отказ
экспорта при невалидном alert; это не универсальный детектор любых утечек.
Изоляция DAG и trusted-vs-PR проверены локально; это не sandbox для произвольного
изменения workflow/host-кода PR и не гарантия отсутствия приватного текста в
любых stdout. Рабочие credentials/пользовательские данные в контур не выдаются.
Перед active scan проверить target/egress всех
профилей, перед расписанием — доставку сигнала и давность. Private content
реальных пользователей в этот локальный профиль не допускается.

Новая граница TZ4/A106: active scanner → reverse proxy gate → ephemeral app.
Gate фиксирует исходные session/Origin и RSC-служебные поля, поэтому результат
говорит об обработке выбранного текста, не о CORS/CSRF, правах или input всех
Actions. Заметки с optimistic concurrency, JSON/файлы и Preview не включены.
Попытки сверх 600 и неизвестные формы блокируются до upstream; polling останавливает
native scan дополнительно. Локально проверены 41 попытка и успешные изменения
выбранного поля обеих Actions, XSS alert на отдельной учебной мишени, отказ
до атак при потере сессии и отказ второй попытки при лимите 1. Это не проверка
всех форм wire, универсальная sandbox-изоляция или гарантия cleanup при hard cancel.

**Открытый вопрос CSP (confirmed, не accepted-risk).** Локальный completed-проход
2026-10-16 подтвердил варианты 10055-4/5/6: `next.config.ts` задаёт base-uri,
object-src, frame-ancestors и form-action, но не default-src/script-src/style-src.
Защита от XSS через CSP поэтому неполна; это не доказательство самого XSS.
ZAP-003 сохраняет исходный Medium/High confidence и статус confirmed.
Для закрытия: отдельная задача на совместимую с Next политику nonce/hash,
проверку исполнения и регрессию UI. Пересмотр до 2027-01-14 либо раньше при
изменении Next/рендеринга/headers или новой находке XSS. Production headers
в этом локальном проходе заново не проверялись.

Месячный ZAP-цикл имеет свой будущий порог давности 40 дней (квартальный — 100).
Ниже существующий восьмидневный триггер image-scan не заменяется этим порогом.

## Эксплуатационный backlog

- request_id Vercel/Cloud Run без содержимого и user identifiers.
- CloudTrail data events S3; сначала сверить current state.
- Отдельный restore-путь/IAM-role, рассмотреть SSE-KMS после сверки bucket policy A82.
- Step-up удаления/управления доступом.
- Минимизация свободного AI-текста и groups FastAPI с сохранением нужного контекста/совместимости.
- Durable retry/reconciliation S3 ↔ Attachment для сирот и удаления данных.

Завершённые rollout/старые digest/migration-plan в [архиве](archive-2026-10-14.md), не backlog и не гарантия нынешнего live-состояния.

## Триггеры полного пересмотра

Новая граница/сервис; модель прав/администратор/viewer; hosting/egress; AI provider/model/location/tools; file origin/типы; DB driver/TLS; credentials/IAM/WIF/control plane; scan/VEX/waiver/provenance/SBOM; второй write-участник; число/доверие пользователей; возобновление Anthropic rule; отсутствие успешного scan дольше восьми дней.

Тариф Neon — PITR/branch/network protection. Защита Vercel — основной домен, preview/unique production URL, exceptions/automation bypass A101. Смена структуры/синтаксиса src/CI — границы detector даже при зелёных тестах.

Публичный Docker/desktop/npm/template артефакт — новый license/distribution review. Выводы hosted-состояния о copyleft не переносятся на распространение без проверки формы доставки.

## Перед расширением доступа

Снятие whitelist — отдельное решение владельца. До него проверить tenant/auth/privacy по потоку, rate/structural/storage/file limits для недоверенных пользователей, cost controls, наблюдаемость/response/restore, минимизацию AI и правовое уведомление. Повторно сверить live-привилегии, backup/bucket/network/protection и переоценить риски малого доверенного круга A12.

Это условия будущего решения, не обещание готовности к публичному запуску и не исчерпывающая compliance-проверка.
